# BUG-003 loadRoomHistory 全量替换导致消息丢失

- **priority**: P1
- **status**: open
- **owner**: —
- **created**: 2026-03-20
- **parent**: BUG-001

## 问题描述

`loadRoomHistory()` 调用 `client.scrollback()` 后读取整个 SDK live timeline，然后用 `setTimeline()` 全量替换 store 中的消息数组。这会导致：

1. 实时同步追加但尚未写入 SDK timeline 的消息被覆盖
2. 通过 `addReaction()` 添加的实时 reaction 可能被旧数据覆盖
3. `mergeStoreReactions()` 是脆弱的 workaround，仅保留 reaction 而不保留其他实时更新

## 复现步骤

1. 打开一个房间，等待 timeline 加载
2. 在另一个客户端发送新消息（实时同步到 store）
3. 在当前客户端向上滚动触发 `loadRoomHistory()`
4. 新消息可能消失（被 `setTimeline()` 覆盖）

## 建议修复

将 `loadRoomHistory()` 改为使用 `prependMessages()` 而非 `setTimeline()`，仅在头部插入新获取的历史消息。

## 影响文件

- `packages/matrix-client/src/services/message-service.ts` — `loadRoomHistory()`
