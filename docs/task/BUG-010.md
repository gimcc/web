# BUG-010 修复快速连发时乐观消息匹配错误

- **priority**: P2
- **status**: open
- **owner**: —
- **created**: 2026-03-20

## 问题描述

`sync-bridge.ts` 中乐观消息确认逻辑：
```typescript
const pendingMsg = timeline.find(
  m => m.eventId.startsWith('~') && m.senderId === myUserId && m.status === 'sending',
)
```

这会匹配到 **第一条** pending 消息。如果用户快速连发 A、B、C 三条消息，服务端可能以 B、A、C 顺序返回（极端情况下），导致：
- B 的真实 ID 被错误地赋给了消息 A
- A 的真实 ID 到达时 A 已被确认为 B 的 ID，于是 A 被当作新消息追加

## 建议修复

方案 1: 在发送时记录 `body` hash 或 `txnId`，匹配时比较内容而非仅靠顺序。

方案 2: 使用 `txnId`（matrix-js-sdk 发送时自动生成），SDK 的 sync response 会携带 `unsigned.transaction_id`，可以精确匹配。

## 影响文件

- `packages/matrix-client/src/sync/sync-bridge.ts`
- `packages/matrix-client/src/services/message-service.ts`
